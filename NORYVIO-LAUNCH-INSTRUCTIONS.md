# Noryvio — підготовка до Cloudflare Pages (етап 1)

## Встановлення
Скопіюйте файли з ZIP у корінь `C:\Projects\noryvio-v2` зі збереженням структури. **Не копіюйте `node_modules`, `.env` або `dist` із старих архівів.**

Список змін:
- `astro.config.mjs` — `site` береться з `NORYVIO_SITE_URL` лише якщо домен визначено;
- `src/layouts/BaseLayout.astro` — до офіційного запуску `noindex` для звичайних сторінок;
- `src/pages/robots.txt.ts` — режим тестування/публікації;
- `src/pages/sitemap.xml.ts` — тільки Noryvio + чотири статті, без демо та юридичних чернеток;
- `public/_headers` — базові заголовки для статичних відповідей Cloudflare Pages;
- `.node-version` — Node.js 22.23.4, який вимагає версія Astro 7 у проєкті.

## Тестовий режим — використовувати зараз
В Cloudflare Pages у змінних середовища **не задавайте** `NORYVIO_LIVE` або вкажіть `false`. `NORYVIO_SITE_URL` поки залиште порожнім (або не задавайте). Також не вмикайте реальні платежі.

Після збірки: `robots.txt` містить `Disallow: /`, сторінки через BaseLayout мають `<meta name="robots" content="noindex, nofollow">`, sitemap порожній. Це **не контроль доступу**: тестовий сайт усе одно може бути відкритим за прямим посиланням; для приватного тестування застосуйте Cloudflare Access.

## Публічний режим — ТІЛЬКИ після юридичної та технічної готовності
Для продакшн-збірки налаштувати build-time змінні:
```
NORYVIO_SITE_URL=https://ВАШ-РЕАЛЬНИЙ-ДОМЕН
NORYVIO_LIVE=true
```

Використовуйте реальний домен без шляху, із HTTPS, не `pages.dev` як остаточну canonical-адресу. Після зміни змінних виконати НОВУ збірку і розгортання. Тоді звичайні публічні сторінки отримають canonical, robots відкриється, sitemap наповниться. Юридичні сторінки з локальним `noindex` **не стануть індексованими**, поки не завершите й не перевірите їхній вміст.

ВАЖЛИВО: при `NORYVIO_LIVE=true` sitemap містить тільки головну, каталог і чотири статті; демосайти лишаються окремими демонстраціями, а не сторінками реальних компаній. Наразі відсутні готова англійська версія, остаточний OG-preview, юридичні реквізити, аудит cookies та продакшн-тест Worker/Turnstile. Не вважайте цей ZIP дозволом приймати оплату.

## Cloudflare Pages
1. Завантажте чистий Git-репозиторій без `.env`, `node_modules` та `dist`. Переконайтеся, що токени не потрапили в історію Git; якщо потрапили — змініть їх у провайдерів.
2. Cloudflare → Workers & Pages → Create application → Pages → Import existing Git repository.
3. Framework: Astro; production branch: main; build command `npm run build`; output directory `dist`.
4. Під час тестового запуску `NORYVIO_LIVE=false` і не задавайте `NORYVIO_SITE_URL`. Worker і Turnstile налаштовуються окремо й тестуються на `pages.dev`.
5. Відкрийте `/robots.txt`, `/sitemap.xml`, головну, `/blog/`, `/templates/`, всі 5 демо. Перевірте відповідь форми та мобільну версію.
6. Після затвердження документів, реєстрації діяльності, вибору домену й SEO-фіналізації налаштуйте домен та build-time змінні, повторіть збірку.

## Локальна перевірка (PowerShell)
```
node --version
npm ci
npm run build
npm run preview
```
Версія Node має бути **не нижча за 22.23.4** згідно з `package.json`. На Cloudflare зафіксована через `.node-version`.

ПРИМІТКА ПРО ПЕРЕВІРКУ: вихідний архів містив Windows `node_modules`; у Linux-середовищі перевірки вони не працюють, а перевстановлення залежностей завершилося тайм-аутом. Тому повний тест Astro-збірки цим середовищем не підтверджено. Синтаксис `astro.config.mjs` перевірено окремо.
